# ProxyWin 0.5.6

This maintenance release fixes reproduced availability problems in window shutdown, profile saving, HTTP CONNECT and local proxy identification. It also removes per-match CIDR address-array allocations and expands regression coverage.

## Fixes and behavior changes

- **Idle window shutdown:** closing a window with no active driver sessions no longer recursively calls `Close()` during WPF's `Closing` event. Cleanup yields to the dispatcher before the final close.
- **Failed settings saves:** a rule checkbox returns to its saved value after a file-sharing violation. Enabling an existing rule from an observed connection no longer reports success when persistence fails. Editing recovers after the file is unlocked; the encrypted profile remains unchanged on failure.
- **HTTP CONNECT compatibility:** successful 2xx responses establish the tunnel, interim responses are consumed before the final response, and complete headers ending exactly at the 16 KiB limit are accepted. The shared header budget and 10-second timeout remain bounded, and initial binary tunnel bytes are preserved.
- **Local proxy ownership:** listeners are matched by address, address family and port instead of port alone. Loopback aliases such as `127.0.0.2` are recognized. Fresh owner lookup is retained.
- **Stable profile paths:** relative profile directories are resolved once when the store is created, so changing the working directory does not redirect later loads or saves.
- **CIDR matching allocations:** stack-backed comparisons preserve IPv4/IPv6 boundaries. The same warmed test measured 4,320,000 allocated bytes before and 0 after across 40,000 calls; this is a method-level measurement, not an application throughput claim.

## Regression coverage and evidence

Eleven additional regression groups cover HTTP response boundaries and tunnel bytes, real IPv4/IPv6/dual-mode listeners, concurrent relays, cancellation cleanup, mapping capacity, profile paths and CIDR matching. The published GUI fixture exercises real save failures, recovery after unlocking and completed idle-window shutdown. Dispatcher failures are retained instead of being overwritten by a PASS report.

## Download and upgrade

1. Download `ProxyWin-0.5.6-win-x64.zip` and its `.sha256` file from this release.
2. Stop routing and monitoring, close the old application, and extract the entire new ZIP into its own folder.
3. Keep the runtime files and `driver` directory together, then run `ProxyWin.exe` as administrator.

The package targets Windows 10/11 x64 and is self-contained; no separate .NET installation is required. Existing DPAPI-protected settings remain at `%LOCALAPPDATA%/ProxyWin/profile.dat`; this release does not change the profile format.

Verify the downloaded archive in PowerShell and compare the result with the accompanying checksum file:

```powershell
Get-FileHash .\ProxyWin-0.5.6-win-x64.zip -Algorithm SHA256
```

## Remaining limits

Multi-day operation, sleep/resume, VPN coexistence, arbitrary interface changes, all remote proxy vendors and public IPv6 interception remain unverified. Packet-fragment handling and fresh process-owner queries retain their documented limits. The local soak recorded one Windows `Volsnap` event ID 36; attribution to ProxyWin was not established. Successful traffic checks do not establish an error-free Windows System log or guarantee uninterrupted operation.
